## Contract

Schema 10 and applied migrations 001–010 remain byte-identical. Catalog 11 (854 identities/269 aliases/50 nodes) and app 0.1.0 unchanged. Typed/Zod IPC lists bounded descending metadata with keyset cursors (1–100, UI20), verifies and reads one snapshot, compares a historical version with current committed content or another historical version, and restores with expected revision. Honest baseline labels show actual capture meaning, not invented earlier edits. Archived/trash history remains readable; restoration requires explicit return to active.

Comparison uses the frozen exact-content projection plus captured labels: IDs, ordered array positions, nullable strings, `1.250` vs `1.25`, units, all structured-step fields and association sets are visible. Private Markdown, organization, lifecycle and timestamps are excluded. Historical names are shown without substituting identities. UI renders comparison data as escaped text; full snapshots are fetched singly, metadata pages are bounded, difference rendering starts at50 rows. Further historical comparison targets can be loaded using older-page control.

Restore is a Rust-owned IMMEDIATE transaction: CAS, active lifecycle, no active edit draft, supported retained formats, selected/latest checksum/header/fingerprint validation and required ingredient/unit ID checks precede writing. The common writer receives an explicit restored-from capture context so exactly one new `restored` row is appended; no intermediate `edited` row. Existing snapshots/recipe UUID/creation date, selected line and step IDs/order/exact quantities/links remain. Independent private Markdown and organization are untouched. IDs occupied by another recipe reject atomically, never remap. Current ingredient labels reflect the current definition, while old snapshots retain historical labels; restoring content does not rename catalog/personal definitions. Identical content returns changed=false without a recipe revision/timestamp or history write. No restore API closes/discards drafts.

A save/restore error rolls back all authoritative rows, search index and history. Unsupported future formats block restoration. Checksums are integrity aids, not authenticity signatures or encryption. M5B-1 immutable/reference tests remain. No history deletion/pruning, restore-as-duplicate, variations, substitutions, media, Cooking Mode or conversion support is introduced.
