# M3D-5 native and performance verification — 2026-10-22

An unsigned **production** macOS arm64 `.app` built with temporary identifier `com.recipeatlas.m3d5-verification`. This identifier maps to an isolated SQLite profile, separate from the Product Owner's normal `com.recipeatlas.desktop` profile. The test bundle launched with macOS LaunchServices. Its SQLite database reported schema 5, catalog Release 11, **854 canonical identities, 269 aliases, 50 categories**, `PRAGMA integrity_check=ok`, zero foreign-key violations and one successful import. The isolated process was terminated, relaunched as a new process, and the same profile still reported one successful import and unchanged counts. Both isolated test processes were then stopped. The normal profile was not opened or modified.

The computer-use inventory could not expose native windows because macOS was locked and automatic unlock failed. Thus **no Release-11 GUI click, Ingredient Library selection, recipe edit or visual responsiveness check is claimed**. Rust/SQLite tests separately exercise search, ingredient detail, recipe references, drafts, favorites, overrides and exact quantities. Product Owner manual GUI acceptance remains necessary.

The local production binary and `.app` compiled, and the isolated app-only bundle completed. Two local attempts to make the DMG (one inside and one outside the command sandbox) ended at Tauri's `bundle_dmg.sh` without a diagnostic beyond the script failure. DMG packaging is therefore **unverified locally**; the PR macOS runner must determine whether its package job succeeds. This is not a failure of the `.app` launch.

Resource observations are bounded: the first native test process showed **99,936 KiB RSS at 1 minute 19 seconds**, 17 `ps -M` rows and 62 `lsof` rows. A relaunched process showed 114,240 KiB RSS at 11 seconds. These are different warm-up points, with no sustained interaction or idle series; they cannot establish a memory-leak trend or a controlled Release-10 comparison. The DEVOPS-1C lifecycle audit remains the deeper resource baseline. A Rust/SQLite debug test performed 100 Turkish partial searches in **172.854 ms** locally; Release-10's earlier 161.957 ms was from a different run and does not establish a regression. The isolated debug CLI recorded **1023.493 ms** for a clean Release-11 import and **361.249 ms** for Release-10→11, including process startup. These are single-host observations, not performance guarantees.
