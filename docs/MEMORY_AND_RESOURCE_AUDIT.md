# DEVOPS-1C memory and resource audit

Date: 2026-10-16. Scope: the release-8 application on the existing PR branch; no catalog, migration, or user-profile change.

## Code and ownership review

| Area | Observed lifecycle | Assessment |
| --- | --- | --- |
| `AppShell`, `nativeExit`, `theme` | Tauri `request-exit` unlistener and media-query listener are removed by effect cleanup. The recipe page is intentionally retained while hidden to preserve an unfinished editor. | The hidden page and its draft checkpoint timer are intentional state preservation, not evidence of a leak. |
| `useFoundation` | Bootstrap responses are guarded by a generation token after retry/unmount; theme saves serialize through a ref. | No accumulating subscription or polling. An already-started IPC request is not cancellable, but its result is not committed after a stale bootstrap. |
| Ingredient Library/search/detail | Searches debounce at 150 ms, cap SQLite pages at 30, and ignore responses after query change/unmount. Detail responses use the same stale-result guard. | No whole-catalog renderer cache or duplicate event subscription. An in-flight native command can finish after its result is ignored. |
| Ingredient leave confirmations | Three editors held Promise resolvers for sidebar navigation. Two requests before a decision replaced the first resolver; unmount with an open dialog left the current resolver unsettled. | **Confirmed retained pending request.** The three paths now return one shared pending Promise and resolve it as “stay” on unmount. Tests exercise both cases. Save failure still leaves the dialog and edits intact. |
| Recipe editor/draft recovery | Debounce timeout, periodic checkpoint interval and native exit guard clean up on unmount. `DraftSession` serializes writes through a single tail Promise. | **Confirmed slow-worker queue risk:** before the fix, the 2-second periodic timer added another `flush` Promise even while a prior periodic write was stalled, retaining queued input snapshots. The timer now allows one periodic write in flight and resumes after settlement. A separate debounce still captures later edits. A focused fake-clock test holds the SQLite client promise unresolved for 9 seconds and verifies no periodic backlog. |
| Rust `StorageService` | One worker thread owns one `rusqlite::Connection`; dropping the sender closes the receiver loop and connection. `oneshot` replies are dropped when request consumers go away. SQLite statements and transactions use RAII; import writes are transactional. | No observed thread/descriptor accumulation in the isolated launch. `std::sync::mpsc` is unbounded, but ordinary UI paths debounce searches and a single SQLite worker processes them. A stalled worker plus automated/malicious high-rate IPC could still queue work without hard backpressure. No architecture change without a reproduced realistic growth case. |
| Catalog startup/retry | Bundled release is checksummed and version-checked. An unchanged installed release avoids import writes. Initialization retries after failure instead of resetting data. | The release-8 package was installed once in the isolated profile. Repeated error/retry stress and long catalog upgrades still need native workload profiling. |

## Native measurement method and evidence

An unsigned **production** arm64 `.app` was built with Tauri config override `com.recipeatlas.devops1c-verification` and application data under `/private/tmp/recipe-devops1c/profile`. The normal `com.recipeatlas.desktop` profile was not opened. The isolated app launched through LaunchServices; read-only SQLite inspection showed release 8, **647 canonical ingredients, 269 aliases, 50 categories**, `integrity_check=ok`, and no foreign-key violations. Its bundle `CFBundleShortVersionString` and `vmmap` both reported **0.1.0**.

`ps` sampled RSS/virtual size and thread count; `lsof` sampled process file entries every 15 seconds for a bounded idle observation. `vmmap -summary` supplied a physical-footprint cross-check. RSS and physical footprint are different metrics; the very large macOS reserved virtual address space is not an allocation or a leak. Apple `leaks -quiet` reported 417 allocations totaling 20,016 bytes, dominated by an AppIntents/Foundation `NSXPCConnection` root cycle. It also reported that this process is not debuggable and restricted the readable memory. These allocations cannot be attributed to application code from that trace alone.

The first sampler recorded **65 idle samples over 16.05 minutes**, 15–16 seconds apart. RSS started at **71.09 MiB**, peaked there, and finished at **44.84 MiB**; the last ten samples averaged **40.36 MiB**. Threads stayed at **16–19** and open file entries at **63**. This is startup stabilization, not a rising idle trend.

A separately named production bundle (`Recipe Atlas Memory Test`, identifier `com.recipeatlas.devops1c-final`) allowed actual native UI automation. Its isolated profile contained release 8 and the same **647/269/50** catalog totals. The active sampler recorded **78 samples over 6.47 minutes**, 5–6 seconds apart, while the UI performed **48 Turkish/English ingredient searches, 47 detail openings, and category-filter navigation**. RSS began at **97.06 MiB** after UI warm-up, peaked at **126.64 MiB**, and fell to **110.72 MiB** by the final sample. Threads ranged **16–25** and file entries **63–73**. The app stayed running through the session interruption; approximately four hours later its RSS was **85.66 MiB** (`ps`), below the sampled peak. This pattern is consistent with lazy WebView allocation and allocator/cache release. It does not prove that all retained allocations are benign. A further post-workload sample is described below.

After the session interruption and about four hours of app uptime, a further **61 post-workload samples over 5.07 minutes**, 5–6 seconds apart, showed RSS declining from **85.67 to 71.89 MiB** (last ten average **71.89 MiB**). Threads stayed at **16–21** and file entries at **80** throughout this post-workload series. The higher file-entry baseline than the initial 63 followed the opened GUI and recipe workflow; it did not grow across these 61 samples. The sampled process exited on Cmd-Q and released its SQLite file; the separate idle-profile process exited after TERM once its sampling was complete.

The native UI also showed the sidebar and Settings/About version **v0.1.0**, and real catalog counts. A recipe was created using a built-in tomato ingredient, **125.5 g**, and an ordered preparation step; the detail view and read-only SQLite query showed the committed quantity and step. Editing, choosing “continue editing”, then choosing “discard changes” returned to the original committed recipe without replacing it. The final-code arm64 bundle was rebuilt after the last source change, launched against the same disposable profile, and showed the committed recipe, ingredient quantity, step, version and **647/269/50** catalog counts after full app restart. A final Cmd-Q closed the process and released its SQLite file. SQLite reported `integrity_check=ok` with no foreign-key violations. The normal personal profile was not opened by these test bundles.

Temporary sampler CSVs are under `/private/tmp/recipe-devops1c/` and are not committed. The first two samplers stopped when the prior Codex session was interrupted, so their observed durations are shorter than the planned 30-minute idle and 15-minute active windows. These bounded samples, native GUI actions, and the restricted `leaks` report support only a limited conclusion: **no sustained resource growth was demonstrated in this workload**. They cannot establish that the application is memory-leak free. Repeated native async error/retry cycles, long catalog upgrades, Intel macOS, and Windows were not profiled locally. Renderer tests and SQLite-backed Rust tests are separate evidence, not substitutes for native GUI behavior.

## Verification and remaining work

The scoped regression tests cover version metadata request/failure, sidebar and Settings/About rendering, one-shot/cancelled ingredient leave decisions, and suppression of repeated periodic draft flushes while a write is stalled. `tools/check_app_version.py` compares `package.json`, `src-tauri/Cargo.toml`, and `src-tauri/tauri.conf.json`; PR CI runs it in the inexpensive frontend job. Tauri's installed-version API is already included in `core:app:default`, so no extra permission or dependency was added.

For a fuller native workload, use a disposable app-data override, record its process PID from `lsof` on that profile's SQLite file, and sample RSS/physical footprint, threads and file descriptors before warm-up, after 100 ingredient searches/category/detail cycles, after repeated recipe create/edit/cancel/recovery and error/retry cycles, after a 10-minute idle period, and after a full quit/relaunch. Compare post-idle values over several cycles and inspect heap retention with a debuggable local build; do not use the normal personal profile. Repeat on Intel macOS and Windows x64 hosts. A green PR package job proves compilation and packaging, not GUI or long-duration leak freedom.
