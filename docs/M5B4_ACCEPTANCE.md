## Delivered behavior and deliberate limits

Each stable primary line owns up to10 distinct alternatives (1000 total per recipe). Alternatives have independent stable UUIDs, valid real ingredient IDs and optional exact user-entered quantity/unit. Same target twice on one line or self-alternatives are rejected; the same ingredient may occur independently on multiple lines. Units reference existing stored codes; NULL quantity/unit are independent unknowns. Quantities use the established positive12-whole/6-fraction decimal-text convention, never floating point. Drafts retain unfinished text. No density, nutrition, alcohol or measurement equivalence is inferred.

Expandable panels keep Quick Add simple; only expanded controls mount, and reference discovery remains bounded. Add/edit/reorder/remove are draft operations. Changing an alternative's ingredient keeps its alternative UUID but clears the prior quantity/unit with a notice, avoiding transfer across identities. Reference-only search cannot create ingredient definitions while editing alternatives; existing ingredient management remains available separately. Duplicate targets and limits receive Turkish feedback; invalid quantity fields are marked.

Use Alternative opens an accessible review dialog outside the recipe form. Its inputs are populated only from that alternative, never the original line. Missing unit requires explicit selection; missing quantity requires an explicit unknown-quantity acknowledgement or entry. Enter inside a review input cannot submit the outer recipe Save. Confirming Use consumes the selected alternative into the primary line, retaining the primary line UUID/step links; it does not automatically invent an alternative for the former primary. No authoritative recipe/version write occurs until separate Save (durable draft autosave remains intentional). Removing an owner line warns before draft mutation, identifies the line/count, and Cancel keeps the draft unchanged. Reorder/unrelated edits preserve alternative IDs and data.
