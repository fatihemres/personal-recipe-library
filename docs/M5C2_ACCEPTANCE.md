## Delivered model and lifecycle

Zero/one optional photo per stable step UUID. `photoAssetId` is a strict optional/nullable UUID at typed input boundaries. New format4 snapshots explicitly serialize null when absent. Reorder moves the entire step identity, never an index-based photo mapping. Add/replace/remove and confirmed photographed-step deletion modify the editor/durable draft only; separate Save commits. Cancel preserves the exact step/photo; draft-only photos also require deletion confirmation. Metadata stays optional/simple-by-default. Large preview dialogs are explicit and keyboard-accessible.

Same Rust-controlled native picker and ImportGate as cover images; no arbitrary renderer path argument, new capability, new dependency or network access. Existing static JPEG/PNG/WebP decoder validation,20,000,000-byte/30,000,000-pixel limits, animation/HEIC rejection, orientation/transparency handling, EXIF/GPS stripping and relative immutable UUID keys remain unchanged. Original selected files remain untouched. Existing ICC/HDR/encoding limitations remain; no claim of original-byte equality or universal color fidelity. Source paths are not stored in recipes/history.

Current, active-draft and immutable-history ownership is independent. Migration014 adds `recipe_step_media`, `draft_step_media`, `recipe_version_step_media`; restrictive asset FKs and ready/ownership guards apply. Existing writer deletes/reinserts steps inside CAS; associations are reconstructed by stable UUID **before** history capture in the same transaction. Draft payload/pins/close are atomic. Drafts may be unfinished; valid photos survive recovery before title/instructions are complete. Batched reads do not decode media.

Format4 capture also pins covers and ingredient alternatives: migration014 extends the format-specific migration013 triggers rather than merely adding a step table. Formats2/3 retain their original capture behavior. Historical format1/2/3 bytes, checksums and comparison projections stay frozen; semantic comparison treats old absent photos as null, so no format-only version. Restore of an old photo-less version warns and clears current step associations as new committed content; old files/history remain. Unknown formats reject safely. Duplicate, Variation and Save As New remap step IDs but share immutable asset UUIDs; Duplicate private-note copy and Variation isolation remain unchanged.

No physical media deletion or automatic GC. Archive/Trash preserve associations; reviewed target-only purge removes owned links/history, never another recipe or immutable asset files. Active orphan drafts retain their own pins. SQLite snapshots alone are **not** complete portable media backups; M9 must copy a consistent manifest/file reference set with integrity validation. Schema14 is forward-only; older binaries do not downgrade it.

Migration014 SHA-256: `aabbac13743d3b6b4b260dc58919177e03a31e4d6b2b14015f1778aa3c8f572e`. Applied migrations001–013, production catalog/history, package lockfiles and dependency versions are unchanged.

2. Create a disposable recipe with two stable steps. Add different local photos (JPEG/PNG/static WebP), inspect preview, replace/remove; picker Cancel unchanged. Confirm original files untouched; test HEIC error and orientation/alpha using representative files.
